# Nodio 0.6.3

**Release date:** June 2026

When confirming write actions from the AI assistant or external MCP clients, Nodio now shows a **preview** of the planned change — not just raw JSON. The MCP server panel also has a **Console** tab with an activity log and a visible approval queue. The canvas refreshes reliably after MCP writes; auto-approve is available as **Off / Session / Always**.

---

## New

- **MCP console in the server panel:** From the MCP icon in the title bar (or the floating MCP window), the **Console** tab shows a live log of MCP commands, a list of pending write approvals, and buttons to approve, reject, or **bring to front** a waiting action. The log can be exported (JSON, NDJSON, text) or cleared. The panel is wider so the log and queue stay readable.

---

## Improvements

- **Assistant confirmation with preview:** The “Confirm assistant action” dialog has a **Preview** / **Raw** switcher. Preview shows e.g. a new note as a canvas card (title, body, tags), groups as frame previews, connections as source→target, or delete actions with warning styling. **Raw** still shows the full JSON structure.
- **MCP approvals under parallel writes:** Multiple confirmation dialogs are queued (overlay shows “1 of N”). Pending requests stay visible in the MCP console even when the main window was in the background.
- **MCP hints against duplicates:** Server instructions and tool descriptions for group/note creation tell AI clients to check existing entries first.
- **MCP auto-approve (Off / Session / Always):** In MCP settings and the server panel (Status tab) you choose whether each write needs confirmation. **Session** lasts until the MCP server restarts; **Always** is persisted. For MCP requests, the confirm dialog offers **Approve & auto-approve session** — review the preview once, then further MCP writes in that session run without another prompt.
- **MCP confirm fallback polling:** The global confirm dialog loads pending requests on start and polls every five seconds when idle if a push event was missed — the console remains the visible fallback.
- **MCP popout resizes with content:** The floating MCP window grows with its content (no fixed height with a scrollbar on the window chrome).
- **Update check on startup:** When automatic updates are enabled, Nodio now checks for updates immediately on launch. After that, it checks again roughly every 30 minutes — with a random offset so installations don't all hit the update server at once.
- **Changelog from About:** Under **Settings → About**, **View changelog** opens the in-app release notes window — no longer the website in a new tab. Already loaded notes are cached so reopening does not fetch from the network every time.
- **Roadmap stays current:** The About roadmap is refreshed in the background on every update check (startup, interval, manual “Check for updates”). When content changes, the view updates even if About is already open. Offline, Nodio shows the last successfully loaded roadmap.
- **World Canvas — smoother panning:** The main canvas view no longer re-renders on every pan frame. Edges outside the visible area are culled with nodes; connection labels are hidden while dragging the pane to reduce DOM work.
- **Faster switching between Canvas, Views, and Board:** Notes, groups, connections, and canvas objects stay in memory while you move between screens in the same project — no full SQLite reload on every navigation.
- **List view opens faster:** When switching from World Canvas to list view, Kanban boards, workflow statuses, and note types are no longer reloaded from the database on every open — they come from the same project cache as the note list. Columns, filters, and sort settings still load as before.
- **Smoother switchers:** The World Canvas / list view / board segment control (top bar) and other segment switchers and toggles in the project dashboard slide smoothly again — even while content is still loading in the background.

## Bug fixes

- **Invisible MCP approvals:** When an external client (e.g. Cursor) requested many write actions in parallel, only one confirmation could appear — the rest timed out invisibly and the client seemed frozen. All open approvals are now queryable and manageable from the console.
- **Canvas after MCP groups/connections:** After confirmed MCP writes (e.g. creating or moving groups), the world canvas did not always refresh. All mutating MCP tools now trigger a canvas update.
- **Left connection anchors:** Incoming and outgoing edges on the left side of notes and collapsed groups now attach at the same point — no longer offset between top and center.
- **Canvas flickering fixed:** An internal render loop (selection state and LOD samples) kept the world canvas re-rendering continuously — visible as flickering and FPS drops even at idle. The loop is eliminated; the canvas no longer renders needlessly while idle.
- **Notes disappearing inside groups:** While panning/zooming, notes inside groups could be hidden even though they were visible on screen — only their connections remained. Cause was a position mismatch between rendering and visibility culling for notes whose stored coordinates lay outside their group bounds. These notes now stay visible correctly.
- **Level of detail (LOD) calmed down:** Right after opening a project, the adaptive LOD kicked in due to first-frame dips (brief flash), and zooming out could hide notes entirely. Now: a grace period after opening, zooming out never hides notes, and degradation only applies at idle after sustained low framerate — no longer on short hitches.
- **Settings — shared live channel:** With canvas, views, and other areas open at once, an internal warning about too many parallel settings listeners could fire. Nodio now shares live settings through one central channel — changes still apply immediately across all views.
